# Файлы маскировки Hysteria

Режим File в общей форме установки/редактирования поддерживает отдельные файлы
и один ZIP с вложенными каталогами. Каждая загрузка заменяет весь черновой набор.
Удаление файла создаёт новый набор; исходный набор не изменяется.
В черновик можно загружать наборы без `index.html` и удалять этот файл.
При сохранении/применении режима File обязателен `index.html` в корне набора;
`site/index.html` и `INDEX.HTML` не подходят. Проверка выполняется в форме,
API сохранения/установки сервера и на агенте перед размещением файлов.

Ограничения: 128 файлов, 256 каталогов, 4 МиБ на файл, 8 МиБ распакованных данных, 2 МиБ
канонического ZIP. Архивы проверяются стандартной библиотекой Go `archive/zip`.
Запрещены абсолютные пути, `..`, обратные слеши, управляющие символы, симлинки,
специальные файлы, дубликаты и конфликты файл/каталог. Контролируются объявленный
и фактический размеры распаковки. Права файлов не импортируются из ZIP.

`POST /<admin-prefix>/api/v1/nodes/hysteria-files` принимает multipart с `files`
или `archive`, либо JSON `{source_id, remove_paths}` для удаления из черновика.
Ответ содержит только ID, пути, размеры и общий объём, без содержимого файлов.
Действуют права `nodes.write`, CSRF-защита и ограничение частоты запросов.

Содержимое хранится зашифрованным штатным SecureStore в отдельной таблице
`hysteria_masquerade_filesets`. ID — SHA-256 канонического ZIP. Настройки хранят
только ссылку `file_set_id`. База закрепляет desired и last-applied наборы;
последний освобождается только после ACK актуальной версии. При новой загрузке
удаляются незакреплённые черновики старше 24 часов. Удалённые серверы освобождают
свои ссылки. Наборы участвуют в обычном резервном копировании БД.

При сохранении агент получает ZIP по существующему gRPC stream, повторно
проверяет SHA-256, пути и лимиты. Размер ZIP оставляет запас до стандартного
лимита gRPC в 4 МиБ. Файлы размещаются в отдельном неизменяемом каталоге
`/var/lib/lazgate-hysteria-files/<id>`. Родительский каталог управляется root,
чтобы процесс Hysteria не мог подменить пути при установке. Каталог вручную не задаётся.
Смена активного набора происходит только после полной установки файлов, через
штатное применение конфигурации с проверкой работоспособности и rollback.
После успеха агент оставляет текущий и предыдущий наборы, удаляя более старые.
На новом gRPC-соединении desired configuration отправляется повторно, даже если
предыдущий ACK уже получен: агент может восстановить файлы из БД после потери
локального кеша. В Docker для файлов выделен отдельный persistent volume.

Для файловых операций и перезапуска сервиса агент использует существующие sudo
правила установки. Поэтому его systemd unit не должен запрещать повышение прав
через `NoNewPrivileges=true`. Сохраняются отдельный пользователь, `ProtectSystem`,
`ProtectHome`, `PrivateTmp` и явный список `ReadWritePaths`. Новый root-каталог
создаётся установщиком и удаляется при полном удалении Hysteria, но сохраняется
при отключении только агента от LazGate.

Необходимо обновить сервер и Hysteria agent вместе. Схема, как и остальные
изменения текущей разработки, предназначена для чистой установки.

Содержимое маскировки публично. Загружать конфигурации, ключи и другие секреты
нельзя. Скрипты PHP и подобные файлы не исполняются: это статический файловый
сервер Hysteria.
