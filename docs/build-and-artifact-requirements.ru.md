# Требования к сборке и изоляции артефактов

Статус: обязательное архитектурное требование для целевой реализации LazGate.

## Общая модель

Проект остаётся в одном репозитории и одном Go module. Переход на несколько
Go modules не требуется.

Проект должен предоставлять три независимо собираемых приложения:

- LazGate Server;
- LazGate Hysteria2 Agent;
- LazGate AmneziaWG Agent.

Каждое приложение должно иметь собственную точку входа, собственный граф
зависимостей и собственный release artifact. Сборка одного приложения не должна
требовать включения runtime-кода другого приложения.

## Границы зависимостей

Обязательны следующие ограничения:

- Server не зависит от runtime-реализаций агентов;
- агенты не зависят от Server, его HTTP/UI и server-side storage;
- Hysteria2 Agent не зависит от AmneziaWG Agent;
- AmneziaWG Agent не зависит от Hysteria2 Agent;
- общий код агента не содержит protocol-specific runtime, storage schema или
  конфигурацию;
- общий protocol-код не содержит runtime-реализации конкретного VPN;
- protocol-specific контракты и payload не должны попадать в приложение,
  которое соответствующий протокол не использует.

Границы должны проверяться автоматически по фактическому Go dependency graph,
например через `go list -deps`. Нарушение границы должно завершать CI с ошибкой.

## Требования к агентам

Каждый protocol-specific агент является самостоятельной deployable unit, а не
режимом работы общего универсального agent binary.

Для Hysteria2 Agent и AmneziaWG Agent обязательны:

- отдельный исполняемый файл;
- отдельный final OCI image;
- независимые конфигурация и lifecycle процесса;
- независимое локальное состояние и собственный набор миграций;
- возможность независимой установки, обновления, перезапуска и удаления;
- включение только нужного данному агенту VPN runtime и системных инструментов;
- отсутствие кода, конфигурации, миграций и runtime-зависимостей второго агента;
- использование только общего wire contract и минимального действительно
  общего infrastructure-кода.

На одной node разрешено одновременно запускать несколько типов агентов. В этом
случае они остаются отдельными процессами и deployment units, не разделяют
protocol-specific state и не требуют совместного обновления.

Добавление нового VPN-протокола должно приводить к появлению нового
самостоятельного агента и артефакта, а не к расширению существующих agent images
чужими runtime-зависимостями.

## Release artifacts

Server и каждый агент выпускаются независимо. Для поддерживаемых платформ
должны создаваться отдельные бинарные артефакты и checksums.

Изменение одного агента не должно требовать выпуска или установки другого
агента, если общий wire contract остался совместимым.

## OCI images

Для агентов должны собираться отдельные final OCI images:

- LazGate Hysteria2 Agent image;
- LazGate AmneziaWG Agent image.

LazGate Server устанавливается нативным бинарником через systemd; production
image не требуется. Docker-окружение сервера используется только для разработки.

Final image должен содержать только бинарник соответствующего приложения и
минимально необходимые ему runtime-зависимости. В него не должны попадать
бинарники, web assets, миграции, инструменты или runtime-зависимости других
приложений.

Конкретные Dockerfile, build targets, build contexts и перечни директорий,
которые участвуют в сборке каждого image, будут определены отдельно при
переносе соответствующего кода.

## Критерии готовности

Требование считается выполненным, когда:

1. каждое из трёх приложений собирается отдельной командой;
2. для каждого приложения создаётся отдельный release artifact;
3. для агентов создаются отдельные final OCI images; сервер устанавливается нативно;
4. dependency checks подтверждают установленные границы;
5. состав каждого binary/image не включает код и runtime-зависимости двух
   других приложений без необходимости общего wire contract;
6. каждое приложение можно обновить и развернуть независимо.
